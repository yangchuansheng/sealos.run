## 为什么大肥鱼会「失忆」并疯狂烧 Token？

每次对话都会将近期历史消息重新打包发给大模型，上下文越长单次 Token（「白饭钱」）越高，而一旦触达上下文上限触发压缩或容器重启，未落盘的记忆便会瞬间清空。

这也是社区常吐槽的「停在了那个夏天」与「偷米」两大顽疾的共同根因：
- **无界上下文叠加**：连续聊上百轮后，哪怕只发一句「早安」，请求也可能附带数万 Token 的历史记录；
- **易失性本地状态**：本地 Docker 容器未挂载持久化卷，或旧手机后台被系统杀进程清理缓存，重开后人格关系归零；
- **定时任务死循环**：生物钟脚本或插件未设冷却阈值，在夜间反复唤醒重试，天亮时 API 额度已消耗殆尽。

## 防失忆方案一：善用 AstrBot 官方模板持久化数据卷与知识库

Sealos 上架的 AstrBot（`v4.29.4`）与 MaiBot（`v1.4.5`）官方模板默认挂载独立持久化数据卷，即使容器重启、滚动升级或节点迁移，核心配置与内置数据库文件也不会丢失。

- **AstrBot 持久卷**：默认挂载 `1Gi` 存储到 `/AstrBot/data`，保存会话记录、插件配置、内置 SQLite 数据库与本地知识库索引；
- **MaiBot 持久卷**：默认挂载 `2Gi` 存储到 `/MaiMBot/host` 与 `/MaiMBot/bots`，完整保留多 Bot 人格档案与成长日志；
- **最佳实践**：将关键纪念日、称呼偏好、固定人物关系整理成轻量 Markdown 存入框架知识库（RAG），每次仅检索最相关的 3–5 条片段注入 Prompt，既防失忆又省白饭钱。

## 防失忆方案二：同 Canvas 挂载 Sealos 托管 PostgreSQL / Redis 长期记忆库

对于跨月陪伴、结构化记忆检索或同时承载《大肥鱼观察日记》数据的进阶玩家，直接让 Sealos Desktop 内置 Agent 在同 `Project` `Canvas` 挂载纯内网托管 PostgreSQL 并开启定时备份，是最稳妥的「永生舱」方案。

在桌面端 Agent 对话框直接粘贴：

```text
帮我给当前大肥鱼项目挂载一个轻量 PostgreSQL 数据库（0.5 核 1G 内存、仅内网访问）并开启每日自动备份，把连接串整理出来。
```

确认批准卡（Deploy Plan）后，`Canvas` 会自动绘制应用 `Service` 指向数据库 `Service` 的依赖连线：
- **纯内网零端口费**：托管数据库保持 `0` 公网端口，仅向同 `Project` 内网开放连接；
- **每日自动备份**：一键开启自动快照，误操作改坏表结构或误删记忆可随时回滚；
- **透明增量成本**：按北京可用区（`bja`）720 小时公式核算，完整「AstrBot + NapCat + 托管 PostgreSQL」全家桶月均约 `¥29.98/月`（`¥1.00/天`），详见 [按量费用明细与四方案对比](/blog/deepseek-bot-hosting-cost-comparison)。

## 防「偷米」预算控制：三道硬护栏稳住白饭钱

把上下文轮数上限、作息时间窗与 API 消费封顶三项同时配齐，日常单人陪伴的 DeepSeek API 月消费可以稳定控制在几元到十几元区间。

| 防护项 | 推荐安全区间 | 作用说明 |
| --- | --- | --- |
| **滑动上下文窗口** | 保留最近 `12 – 20` 轮对话 | 超出轮次自动触发摘要归档，避免单次请求携带冗余历史 |
| **作息静默时间窗** | 每日 `01:00 – 07:30` 关闭主动触发 | 仅响应主动私聊，暂停定时播报与巡检任务，杜绝夜间偷米 |
| **API / AI Gateway 消费硬顶** | 设置每日预算阈值与余额告警 | 通过 DeepSeek 后台或 Sealos `AI Gateway` 防止脚本异常循环刷爆额度 |

## 防 412 / 429 平台风控指南：安全冷却参数建议

任何聊天或研究型自动化程序都应将低频克制作为默认行为，优先采用官方渠道，并为所有外发动作配置最小冷却间隔、随机抖动与指数退避策略。

1. **私人 QQ 频率护栏**：开启「仅响应 @ 提及或指定白名单私聊」，单群最小回复间隔设置 `15 – 30 秒`，连续多条消息启用合并防抖（`2 – 3 秒`），避免机器人互怼死循环。
2. **DSH 研究脚本配额限制**：对 `dsh-bili-whale` 等自托管研究工具严格收紧单小时读写次数上限，遇到 `412` 或 `429` 状态码立即暂停队列并指数退避（如 `5 分钟 → 30 分钟 → 暂停至次日`）。
3. **集中观察日志**：通过 Sealos Desktop 实时查看容器日志或直接向内置 Agent 提问「检查最近 1 小时日志里有没有 412 或 429 报错」，第一时间发现异常重试。

## 常见问题（FAQ）

### 为什么大肥鱼聊久了会突然「失忆」并且 Token 越烧越快？
随着对话轮次累积，整段历史会被重复拼进每次模型请求的上下文，导致单次 Token 消耗线性膨胀；当长度触及上限触发 Compact 压缩或本地容器重建时，未外置持久化的细节就会被截断丢失。

### 在 Sealos 上挂载托管 PostgreSQL 数据库会暴露到公网吗？
不会。通过 Sealos Desktop 内置 Agent 在同 `Canvas` 挂载的托管 PostgreSQL 或 Redis 默认纯内网隔离（0 公网端口），只供同一 `Project` 内的应用 `Service` 访问，同时支持开启每日自动备份。

### 如何防止大肥鱼夜间或后台「偷米」烧光 DeepSeek API 余额？
建议同时启用三道防线：在框架内将单次上下文轮数限制在 12–20 轮并开启摘要归档；配置夜间静默作息窗减少无意义定时唤醒；在 DeepSeek API 或 `AI Gateway` 侧设置每日消费硬上限。

### 遇到 412 / 429 频率风控后应该怎样调整参数？
立即停止高频轮询并延长最小请求间隔，将私人 QQ 群聊回复冷却设为 15–30 秒以上并开启随机抖动，研究型脚本须配置严格的每小时读写配额与指数退避重试。
